# quantStrategy
personal quant strategy with backtest

## 실험은 LAA_SANDBOX에서 진행

`strategies/laaMA_sandbox.py`의 설정만 변경해 실험합니다. 이전의 별도
GOLD12 / GOLD12_IWD3 / IWD3_GOLD50 전략과 실행기 등록은 제거했습니다.
기존 LAA_MA4 등 정식 전략은 유지하며 두 실행기의 호환성 테스트를 계속 실행합니다.
과거 실험 결과 CSV는 기록으로 보존합니다.

```powershell
.\setEnv.bat LAA_SANDBOX
```

결과와 함께 `outputs/config_LAA_SANDBOX.json`에 해당 실행의 설정을 저장합니다.
SANDBOX 재실행 시 결과와 설정 파일은 갱신됩니다.

| 설정 | 현재 값 | 의미 |
|---|---|---|
| `VALUE_STRATEGY` | `'REGIME'` | 경기/시장 추세로 IWD 판단 (`MA`, `HOLD`도 유지) |
| `VALUE_STAGED_DEFENSE` | `True` | 단계적 방어 켜기; `False`는 기존 전량 ON/OFF |
| `VALUE_CAUTION_FRACTION` | `0.5` | 하락 추세지만 고용 악화 미확인일 때 IWD 슬롯 보유 비율 |
| `GOLD_STRATEGY` | `'SPLIT'` | 금과 채권 조건을 독립적으로 반영 |
| `GOLD_PRICE_SHARE` | `0.5` | 금 조건의 몫; 채권 조건의 몫은 `1 - 값` |

IWD 단계적 방어는 상승 추세에서 100%, 하락 추세·고용 정상에서 50%,
하락 추세·고용 악화에서 0%입니다. 복귀에도 같은 표를 적용합니다.
단계적 방어 설정은 `VALUE_STRATEGY='REGIME'`일 때만 적용됩니다.

금 모드는 `AND`(금·채권 모두 양수), `GOLD_ONLY`(금만 양수),
`SPLIT`(각 조건의 몫만 투자), `HOLD`(항상 보유)입니다.
`BOTH_NEGATIVE`는 금과 IEF의 1년 수익률이 **둘 다 음수일 때만** 금을
전량 매도합니다. 하나라도 0 이상이면 금 슬롯 전부를 보유/재매수합니다.
두 수익률을 모두 계산할 수 없는 초기 구간이나 결측 구간은 SGOV로 대기합니다.
다른 금 모드와 동일하게 월말 판단이며 `GOLD_STRATEGY = 'BOTH_NEGATIVE'`로 선택합니다.
SPLIT/0.5에서는 두 1년 수익률 조건을 각각 50% 반영하므로 금이 하락해도
채권 조건만 양수면 금을 절반 보유합니다. 0 또는 결측 수익률은 미충족입니다.
월말에 판단하고 다음 거래일 종가에 체결합니다. 잔여 몫은 SGOV입니다.

현재 비중은 사용자가 설정한 QQQ 30% / IWD 25% / 금 20% / IEF 25%,
QQQ 쿨다운 0일을 유지합니다. 과거 각 25%·쿨다운 30일 실험과 비교하려면
이 설정도 동일하게 맞춰야 합니다. QQQ 자금은 별도로 운용하며 월말 리밸런싱하지 않습니다.

개발 시 `python -m unittest discover -s tests -v`로 기존 실행기 호환성,
실험 설정의 켜기/끄기, 월말 신호와 자금 보존을 함께 검증합니다.

## LAA_MA4 / LAA_SANDBOX 백테스트 기준

### 실업률: 당시 이용 가능했던 발표본 사용

두 전략의 REGIME 계산은 ALFRED의 `date`(관측월), `realtime_start`
(해당 값의 공개일), `value`를 사용합니다. 각 월말에는 그날까지 공개된
각 관측월의 최신 수정본만 선택합니다. 최신 FRED 수치를 단순히 한 달
미루는 방식은 사후 수정 문제를 해결하지 못하므로 대체하지 않습니다.

다음 중 하나를 환경변수로 설정해야 합니다. API 키는 저장소에 기록하지 마세요.

Windows에서는 아래 실행 파일을 사용할 수 있습니다. 현재 프로세스, Windows
사용자, 시스템 환경변수 순서로 설정을 확인합니다. 키가 없으면 화면에
표시하지 않고 입력받으며, 해당 실행에서만 사용합니다.

```powershell
.\setEnv.bat                 # 기본: LAA_MA4 실행
.\setEnv.bat LAA_SANDBOX     # 샌드박스 실행
.\setEnv.bat -Check          # Python에 설정이 전달되는지만 확인 (API 호출 없음)
```

이 파일은 환경변수 설정과 Python 실행을 같은 자식 프로세스에서 처리합니다.
따라서 기존 VS Code를 재시작하지 않아도 저장된 Windows 설정을 읽습니다.
실행 후 부모 PowerShell이나 VS Code 실행 버튼의 환경변수를 변경하지는 않습니다.
`-Check` 성공은 키의 전달·형식 확인이며 API 인증 성공을 뜻하지 않습니다.

직접 환경변수를 지정해서 실행하려면:

```powershell
$env:FRED_API_KEY = '<your key>'
# 또는 ALFRED 발표 이력을 보유한 경우:
$env:UNRATE_VINTAGES_CSV = 'C:\data\unrate_vintages.csv'
.\.venv\Scripts\python.exe runBacktest.py LAA_MA4
```

CSV에는 `date,realtime_start,value` 열이 필요합니다. 최신 수치에 임의의
발표일을 붙인 파일은 사용할 수 없습니다. 시작 시점에 최소 13개월의
당시 이용 가능했던 관측값이 필요합니다. 이력이 부족하면 오류를 내며,
경기 확장으로 임의 처리하지 않습니다. 이 수정은 MA4와 SANDBOX에
적용되며, 다른 기존 전략의 실업률 로직까지 변경한 것은 아닙니다.

자료: [ALFRED 관측값 API](https://fred.stlouisfed.org/docs/api/fred/series_observations.html)

### 거래일과 체결

- NYSE 휴장일을 포함한 실제 월말 거래일에 IWD/금 신호를 확정합니다.
- 기본값은 신호 확정 다음 거래일 **종가 체결**입니다. 그날 수익률은
  기존 보유분에 귀속되고, 새 보유분은 그 다음 거래일부터 수익을 얻습니다.
  시가 데이터가 없는 지수 프록시에 시가 체결을 가정하지 않습니다.
- MA4는 초기 자금을 QQQ↔SGOV 25%와 나머지 75%로 분리합니다.
  QQQ는 신호가 바뀔 때만 해당 운용 자금 전액을 전환하고, 보유 중에는
  월말에도 리밸런싱하지 않습니다. 현금 대기 중인 자금도 별도로 유지합니다.
  IWD·IAU·IEF는 나머지 운용 자금 안에서 월말에만 동일 비중으로 복원하며,
  OFF인 자산의 몫은 SGOV로 보유합니다. 월중 QQQ 거래로 이들을 조정하지 않습니다.
  초기 진입은 첫 신호 다음 거래일 종가이며 이후 정기 리밸런싱과 구분합니다.
  QQQ의 전체 포트폴리오 비중은 이후 수익률에 따라 25%에서 달라집니다.
  SANDBOX도 설정된 공격 자산과 초기 비중에 같은 방식을 적용합니다.
- 거래 기록에는 목표 비중 차이가 아닌 실제 체결 직전 비중과 거래 금액을
  기록합니다. 거래비용은 0입니다. 수정가격 기준으로 분배금은 재투자됩니다.
- `run_backtest(rebalance='changes')`는 목표 변경 때만,
  `rebalance='daily'`는 매일 리밸런싱합니다.
- `shift_weight=False`는 동일 종가 체결을 허용하는 낙관적 모드입니다.
- 모든 전략의 백테스트 실행기에서 가격 이력이 시작되기 전의 매수 목표는 SGOV로
  대체합니다. 최초 유효 가격을 관측한 날부터 원래 목표를 복원하고 다음
  거래일 종가에 체결합니다. 대체 기간은 실행 로그에 표시합니다.
  예를 들어 QQQ 신호용 `^IXIC`는 있어도 성과용 `^NDX`가 아직 없는 기간에
  가상으로 QQQ를 보유하지 않습니다. 이 기간의 장기 성과는 현금 대기를 포함합니다.
- 모든 전략의 중간 가격 누락 시에는 리밸런싱 전체를 유효한 체결가격이
  있는 다음 거래일까지 보류합니다. 대기 중에는 기존 자산을 보유하고,
  새로운 적용 대상 신호가 나오면 대기 목표를 갱신합니다. 보류 횟수는
  로그에 표시하며, 마지막까지 가격이 없으면 미체결로 남깁니다.
  공용 엔진의 기본값 `missing_execution='raise'`는 오류를 내며,
  `runBacktest.py` 실행기는 모든 전략에 명시적으로 `'defer'`를 사용합니다.
  매수 대상 자산의 전체 다운로드가 비어 있어도 오류를 냅니다. 보유 자산의 일시적
  가격 누락은 마지막 평가가격을 유지하므로 원천 데이터 품질 점검은 필요합니다.

분리 운용은 `run_backtest(signal_only_asset='QQQ', signal_only_weight=0.25)`로
선택합니다. 거래 기록의 `sleeve`는 `signal` 또는 `monthly_core`로 표시되며,
같은 SGOV라도 두 운용 자금의 거래를 별도로 기록합니다.
일반 체결/보유 방식은 공용 백테스트 엔진을 사용하는 다른 전략에도 적용되지만,
분리 운용은 MA4/SANDBOX 실행기에만 설정했습니다.
월별 전략과 경기 판단은 NYSE의 실제 마지막 거래일에 신호를 생성합니다.
주말·휴일 월말도 포함하며 아직 끝나지 않은 달의 월말 신호는 만들지 않습니다.
월별 목표는 일별 가격 인덱스로 확장한 뒤 상장 전 현금 대기를 적용합니다.
기존 `outputs`는 자동 갱신하지 않으며, 새 결과와 동일한 기준으로 비교할 수 없습니다.

### 채권 상장 전 구간

`1 / 금리` 가격 프록시를 제거했습니다. IEF는 8.5년, TLT는 25년 만기의
가상 액면채를 매일 교체하는 총수익 모형을 사용합니다. 전일 수익률로
설정한 반기 쿠폰과 원금 현금흐름을 당일 금리로 할인하며, 경과한 달력
일수에 따른 보유수익을 반영합니다. BIL은 전일 단기금리의 이자 누적입니다.
ETF 최초 관측일에 가격 수준을 연결하고, 이후에는 ETF 수정가격을 사용합니다.
상장 후 데이터 누락을 프록시로 덮어쓰지 않습니다.

이는 **근사 모형**입니다. IEF에는 10년 금리, TLT에는 30년 금리를
사용하는 평탄 수익률곡선 가정이 들어가며 실제 국채 지수의 만기별 구성,
롤다운, 비용을 정확히 복원하지는 못합니다. 장기 분석은 이 모형을 사용하고,
ETF가 존재하는 구간의 분석을 별도로 비교하는 것이 좋습니다.

### 지수 프록시 (이번 변경에서는 유지)

긴 이력을 위한 지수 사용은 유용합니다. 향후에는 신호용 지수와 성과용
시계열을 분리하고, 성과용으로는 '상장 전 지수 총수익률 → 상장 후 ETF
수정가격'을 연결하는 방식을 권장합니다. 총수익 지수를 확보하지 못한
구간은 가격지수 근사임을 명시합니다. 금 선물은 롤오버를 포함한 투자
총수익과 단순 연속 가격이 다르므로, 현물 금 가격의 긴 이력과 IAU
수정가격을 연결하는 대안을 우선 검토할 수 있습니다.

### 검증

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

네트워크 없이 발표 전후·수정본, 주말/휴장 월말, 채권 금리 충격·이자,
체결 지연, 보유 비중 변동, 실제 리밸런싱 금액을 검증합니다.
전체 14개 전략과 2개 별칭의 실행 경로도 합성 가격·거시 데이터로 검증합니다.
